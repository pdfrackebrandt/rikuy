## High

### H1. A float between `\paragraph{Lead}` and its text: Delete at the heading's end, or a selection from the heading into the text, deletes the float's words, which are drawn elsewhere and never shown as selected
Repro (h4.py): `Intro words first.\n\n\paragraph{Lead}\n\begin{figure}[t]\n\centering\nFIGBODY\n\caption{Cap words}\n\end{figure}\nText of the paragraph here.`
- Caret at the end of "Lead", Delete: the source loses `FIGBODY` (`\centering\n\n\caption`). On main, the same Delete changes nothing.
- Caret before "Lead", Shift+Right ten times: the page shows `Lead\nText ` selected, but the caret's source range is [72,153], which spans the whole figure. Backspace (or typing Q) gives `\paragraph{}…\centering\n\n\caption{}…of the paragraph`. The figure's body and caption text are deleted although the user never saw them selected. On main, the visible selection included the float.

Cause: `App.layoutPass` (src/app.js:612) moves the run in heading after the floats in the DOM and the page, but source offsets keep the old order. `visibleRanges` (src/editor.js:250) and `deleteInput`'s fallback (app.js ~1514) take every segment of every block between the two source offsets, including the moved float's.

Fix: in layoutPass, mark each float that is moved before a heading (`moved` on the item and its element). In `visibleRanges`, and in `fallbackDeleteRange` for a forward delete, skip the segments and atoms of moved floats unless the DOM range actually intersects their element (`range.intersectsNode(el)`). The cheaper alternative is to keep DOM order and draw the float first with CSS `order` in a flex page column.

### H2. Code on an ordinary paragraph makes a verbatim line TeX sets off the page, while the page wraps it
Repro (h3.py): a body paragraph that is one source line of 40 words (how most modern sources and every Rikuy paragraph are written). Code is offered and writes `\begin{verbatim}\nword word …\n\end{verbatim}`. The page draws it wrapped on 3 lines (`white-space: pre-wrap`, 63 px high). pdfLaTeX reports `Overfull \hbox (699.74pt too wide)` (c/code-long), so the text runs 700 pt past the right edge.

Cause: `codeSafe` (src/styles.js:542) checks the characters but not the line lengths. The verbatim drawing wraps, and TeX's verbatim never does.

Fix: refuse Code where a line is longer than the text width in typewriter characters (about 65 at article 10pt; derive it from `textwidth / 0.525em`), with a whyTo that says so. Draw raw verbatim with `white-space: pre` and visible overflow, so the page shows what TeX prints.

### H3. Design › Colors writes `\hypersetup` before `\usepackage{hyperref}` when the preamble's own `\definecolor{accent}` comes first
Repro (c/hyper-before, from links.mjs): `\usepackage{xcolor}\n\definecolor{accent}{HTML}{AA0000}\n\usepackage{hyperref}`, then pick any colour. `\hypersetup{colorlinks,…}` is inserted right after the accent line, above hyperref. TeX reports `main.tex:4: Undefined control sequence` and `Missing \begin{document}`, and the key list is printed as text at the top of page 1. Loading hyperref last is the documented practice, so an accent defined above it is common.

Cause: `linkColorEdits` (src/looks.js:418) places LINK_LINE after the accent's line without checking where hyperref is loaded.

Fix: insert after whichever is later, the accent's line or the `\usepackage{hyperref}` line (`packageLine(src,'hyperref')`). Otherwise use the line before `\begin{document}`, as the no-accent branch does.

### H4. Title on a paragraph of a document whose `\title` is in the body: the page draws a title TeX does not print, and the paragraph vanishes from the PDF
Repro (h5.py b): body `\title{Real Title}\n\author{Ann}\n\maketitle\n\nMy words\n\nText.`, caret in "My words".
- Title is offered.
- Subtitle, Author and Date are refused with "Give the document a title first", although the document has one.
- Choosing Title writes `\title{My words}` into the preamble and cuts the paragraph. The page's title block now shows "My words", but TeX prints "Real Title" because the body's `\title` comes later. "My words" is nowhere in the PDF.

Putting `\title`/`\author` after `\begin{document}` is a very common layout.

Cause: `titleInfo` (src/styles.js:564) reads only the preamble, and `styleR2` (src/cmd/styles.js:300) trusts it.

Fix: have titleInfo also read the body up to `\maketitle` for `\title`/`\subtitle`/`\author`/`\date`, taking the last of each before `\maketitle`, as TeX does. Edit the found command where it stands. Until then, refuse every title part when the body before `\maketitle` holds any of those commands.

### H5. Rename Style is offered for a command the document only redefines (`\renewcommand`), and renaming it breaks compilation
Repro (h6.py, c/rename-renew): preamble `\renewcommand{\emph}[1]{\textbf{#1}}`. The Styles pane lists emph as a character style and `canRenameStyle('char:emph')` is true. Renaming it to `stressy` writes `\renewcommand{\stressy}…`, and TeX reports `LaTeX Error: Command \stressy undefined`. The same holds through the API for any `\renewenvironment`'d environment (`ownStyleOf` accepts every `envDefs` entry).

Cause: `ownStyleOf` (src/cmd/styles.js:506) treats every `textMacros`/`envDefs` entry as the document's own. The parser's DEF_CMDS includes renewcommand and renewenvironment.

Fix: record the defining command on `def` (parser.js 595/615). Make `ownStyleOf` refuse when it is `renew*`, or when the name is in `texNames`. Do the same check in the pane's menu.

### H6. Rename leaves references to the old counter and environment behind, so TeX stops with "No counter defined"
Repro (ren.mjs; c/rename-within, c/rename-counter):
- `\newtheorem{claim}{Claim}`, `\numberwithin{equation}{claim}`, `\newtheorem{lemma}{Lemma}[claim]`, then Rename claim → fact. Both stay `claim`, and TeX reports `No counter 'claim' defined` twice.
- `\newcounter{example}` + `\newenvironment{example}{\refstepcounter{example}…}`, renamed through `runCommand('rename-style',{v:'env:example',name:'sample'})`, the agent API. Every use becomes `sample` but `\newcounter{example}` stays: `No counter 'sample' defined`.
- Also missed (by reading and ren.mjs):
  - thmtools' `sibling=`/`numberlike=`/`sharenumber=claim`;
  - `\@addtoreset{claim}`;
  - fancyvrb `Verbatim[commandchars=…]` bodies, which do execute `\foo`;
  - a `\foo` used in a `.bib` (only .tex/.sty/.ltx are renamed, src/cmd/styles.js:523).

Cause: `renameEdits` (src/styles.js:725 ENV_NAMERS, 729) renames only the first brace argument of non-theorem namers, does not know `newcounter`, and skips option values.

Fix:
- Add `newcounter` to ENV_NAMERS, plus its `[within]` option.
- Rename a later `{arg}` equal to old for `numberwithin`, `counterwithin`, `counterwithout`, `@addtoreset`.
- Rename `[old]` in the third position of `\newtheorem`.
- Rename `key=old` values for sibling, numberlike and sharenumber.
- Include `.bib` files for `cmd`.
- Refuse the rename where a `Verbatim` with `commandchars` mentions `\old`.

Rarer constructs than H1 to H5, but each stops TeX.

## Medium

### M1. Design › Colors on a hand written `\hypersetup` cannot be taken back, and Black then deletes the author's own line
Repro (links.mjs):
- `\hypersetup{hidelinks}`: Colors rewrites it to exactly LINK_LINE. Black then removes the whole line as if it were Rikuy's, so the author's `hidelinks` is gone and the PDF shows boxed links.
- `\hypersetup{colorlinks,linkcolor=blue}`: the same, so colorlinks is lost.
- `\hypersetup{colorlinks=false,…}`: Black leaves `colorlinks` on, so links turn hyperref's red, green and magenta.

Cause: src/looks.js:424 identifies "Rikuy's line" by its text after the fact, and the off branch drops only the `=accent` keys.

Fix: on, when changing a hand written `\hypersetup`, keep a marker of what was there (a `% rikuy: links was …` comment, or Rikuy's own separate line only, never edit the author's). Off then restores those keys, or removes only Rikuy's own line.

### M2. The Format Painter armed from a caret restyles the whole paragraph it paints a few words in
Repro (h5.py c, c2):
- Caret in a `\section`, then painter, then select "beta" in a body paragraph: the whole paragraph becomes `\section{Alpha beta gamma delta.}`.
- Caret in a bold word of a Normal paragraph, then painter, then select "words" in `\section{Head words}`: the heading becomes the paragraph `Head \textbf{words}`. Its number and contents entry are gone, and the same paint inside a theorem pulls the paragraph out of the theorem.

Painting characters onto words should not restructure the document.

Cause: `paintFormat` (src/cmd/font.js:831) applies `P0.style` whenever the destination paragraph can take it, whatever the destination selection is.

Fix: apply the carried style only when the destination is a click (collapsed or a word click) or covers the whole paragraph, mirroring `fpStyleAt`'s whole paragraph test on the source side.

### M3. Pressing a Code block now selects it, and the next typed key replaces the whole block and joins it to the paragraph before
Repro (h2.py): `Before words.\n\n\begin{verbatim}\nint x = 1;…\end{verbatim}\n\nAfter words.`
- Press on the block, then type `Z`. The source becomes `Before words.Z\n\nAfter words.`: the code is gone and the blank line before it is eaten.
- On main, a press opened the source editor, so press-then-type is what existing users will do.
- Backspace and Delete behave the same way. Both are acceptable as one step, but typing is the trap.

Cause: src/app.js:2198 arms code. app.js:1286 disarms on a key but leaves the DOM selection (`selectNode` of the block, which maps to the range from the previous paragraph's end), and the typed text replaces that range.

Fix: while code is armed, a printable key either opens the source (as Enter does) or is swallowed with the toast. If replacing is wanted, replace exactly [info.s, info.e) and keep the paragraph break.

### M4. Title parts ignore a `\title` in an `\input` preamble, and Title then Normal deletes `\maketitle`
Repro (title.mjs case 3 and 14):
- main has `\input{preamble}` (with `\title{T}`) and `\maketitle`.
- Title is offered on a body paragraph, and Author, Subtitle and Date are refused as if there were no title.
- Title writes `\title{My Title}` into main, overriding T.
- Normal on that title then replaces `\maketitle` with the words, so the document loses its title block, which the `\input` title had before.

Cause: `titleInfo` reads main's text only (src/styles.js:564); titleNormalEdits treats the title as standing alone.

Fix: read `\title` and the other parts through `preambleOthers()`. When a title part lives in another file, refuse with a reason rather than writing a second one.

### New defects

**N1 (High, a regression from the L3 fix): Rename skips TikZ `\path` operations as if they were url's `\path|…|`, so a command used in a node is left with its old name and TeX stops.**
Repro (mk2.mjs, v/rename-tikz-path):
- `\newcommand{\lab}[1]{\textbf{#1}}`
- a tikzpicture with `\path (0,0) node {\lab{a}} (2,0) node {\lab{b}};`
- Rename `\lab` to `\lbl`.

`\lab{a}` stays and TeX reports `main.tex:6: Undefined control sequence`. `\path[draw] (0,0) -- …` skips the same way, up to the next `(`.

Cause: INLINE_VERB includes `path` (src/styles.js, renameEdits). After an optional `[…]`, any non-space character is taken as the verbatim delimiter, including `(`.

Fix: for `path` and `url`, skip only a `{…}` group, or a delimiter from `|!+"=/`. Never skip an option group for them, since url's `\path` takes none.

**N2 (Low): Rename refuses the commonest theorem name.**
`\newtheorem{theorem}{Theorem}` is refused with "\theoremautorefname is LaTeX's or a package's own". hyperref defines it, so the check fires. Renaming `\theoremautorefname` together with the environment is what autoref needs anyway.

Fix: leave `name+'autorefname'` (and `+'name'`) out of the clash list, keeping only the `the`/`end` forms that clash with unrelated commands (`\theta`, `\endinput`).

**N3 (Medium, residual of H3): `\hypersetup` can still land above hyperref.**
When hyperref is loaded by `\RequirePackage{hyperref}`, or from an `\input{preamble}`, below a hand written `\definecolor{accent}`, Rikuy's line still goes right after the accent, above hyperref. TeX then stops on `\hypersetup` (req.mjs prints the order). This needs a rarer layout than H3.

Fix: when main has no `\usepackage{…hyperref…}` line, place the line just before `\begin{document}`, which is the existing fallback, and not after the accent.
