## High

### H1. Form Fields corrupt the source and break the compile when a Form already exists anywhere but at the top level
Repro: `form1.py` writes four documents to `form/*/main.tex`. `tc.sh form/*` compiles them.
- `nested_before`: a Form inside `\begin{center}`, caret in a paragraph before it, Form Fields › Plain Text. `\begin{Form}` moves to the top of the body, `\end{Form}` stays inside center. TeX: `\begin{center} on input line 7 ended by \end{Form}`, then `\begin{Form} ... ended by \end{center}`.
- `nested_after`: the same with the caret after it. The mirror image, with the same two errors.
- `commented_form`: the body has the line `% \begin{Form} old draft \end{Form}` and the caret is in a paragraph after it. `formEnv` reads the comment as the Form, and `formEdits` cuts `\end{Form}` out of the comment line (the comment's text changes) and appends a bare `\end{Form}` before `\end{document}`. TeX: `\begin{document} ended by \end{Form}`.
- `two_forms`: the caret is between two Forms. The first Form's end moves to the end of the document, so the second Form ends up nested inside it. TeX accepts this, but there are now two Forms, one inside the other.

Cause: src/forms.js:46 `formEnv` matches the first `\begin{Form}` and the first `\end{Form}` by regex, ignoring comments, verbatim and nesting depth. src/cmd/parts.js:283–300 `formEdits` then moves one of the two tags to the edge of the document without checking what lies between them.

Fix: skip `%` comments in `formEnv` (the cover.js `coverAt` loop already does this). Move a tag only when the Form is the only one and both of its tags stand at depth 0 of the body, meaning no `\begin`/`\end` is left open between `\begin{document}` and the tag. Otherwise put the field in place with no Form edits, or show a toast saying why. Add the four documents above as tests.

### H2. Cover Page in a memoir document does not compile
Repro: `cover1.py`, case `memoir`; `tc.sh cover/memoir`. TeX: `Environment titlepage undefined`, then `\begin{document} ended by \end{titlepage}`. memoir has `titlingpage` and no `titlepage`.

Cause: src/cover.js:70–71 `coverEdits` refuses only beamer. src/cover.js:25 `coverAt` and the model's titlepage handling (src/model.js:2178) know only `titlepage`.

Fix: for `cls === 'memoir'`, write `\begin{titlingpage}…\end{titlingpage}`. `coverAt`, `coverDesign` and the model's page break (model.js:2178) should also accept `titlingpage`. scrartcl, a report with `\maketitle`, twocolumn, and `\title` before `\documentclass` all compiled cleanly.

### H3. A deleted wrapfigure stays drawn when its paragraph becomes the document's first item
Repro: `wrap1.py`. The body is a wrapfigure followed by a paragraph. Delete the wrapfigure in one edit. The source is correct, but the page still draws the figure and its caption "Figure 1: FIGCAP" floated inside the paragraph (`.it.p.has-wrap > .wrap-in`). It stays until the paragraph itself is rebuilt. Typing in the ghost caption does nothing (`wrap2.py`), so the source is not harmed, but the page shows a figure TeX does not print.

Cause: src/layout.js:231 unpairs a paragraph P only while visiting the item before it (`P = items[i + 1]`). Once P is `items[0]`, nothing visits it, so `P.wrapOf` and the moved `W.el` are never removed.

Fix: before the pairing loop, run one pass over every item: `if (it.wrapOf && it.wrapOf !== items[k - 1]) { unpair }`. This covers k = 0 too.

### H4. A wrapped paragraph never breaks across pages: it is moved whole and runs past the sheet
Repro: `wrap3.py`. A short paragraph, then a wrapfigure, then a paragraph of about 1.5 pages. Page 1 shows only "Intro paragraph." and stays blank below it. The wrapped paragraph sits on page 2 from y=1702 to y=4092, but page 2 ends at y=2813, so it runs over page 3, where "Second paragraph here." is drawn at y=3043 under it. TeX puts the figure and the paragraph's first lines on page 1 and breaks the paragraph across pages. Any wrapped paragraph near the foot of a page is pushed to the next page this way.

Cause: src/layout.js:271 `if (it.wrapOf) it.lines = null;`.

Fix: keep the line boxes. A cut below the float's bottom (the float is the first child, so its rect is known) can stay as now. A cut beside the float needs the float kept with the first piece. At minimum, measure lines and allow cuts below the float's bottom edge. The paragraph must never be placed taller than a page.

## Medium

### M1. Dragging selected words onto any input deletes them from the document
Repro: `drag2.py`, case b. Select "alpha beta" on the page and drag it into the search box (`#rk-search`). The search box gets "alpha beta", and the document loses the words: `Start  gamma …`, history `['del']`. The same `deleteByDrag` path runs when the drop target is another tab (including a second Rikuy tab, whose dragover sets `dropEffect = 'move'` because the custom type is present) or another application that accepts a move. I inferred this from the code; I did not drive a cross-window drag. The commit message says "a move never crosses files". The change is undoable but silent.

Cause: src/app.js:1307 handles `deleteByDrag` like any other delete. src/cmd/move.js:30 `effectAllowed = 'copyMove'` lets outside targets choose a move.

Fix: in `onBeforeInput`, ignore `deleteByDrag`: `preventDefault` and do nothing. In-page moves are already done by `moveSource`, and the page's own drop calls `preventDefault`, so this event only comes from outside drops. Also set `dt.effectAllowed = 'copy'` once the pointer leaves `#pages`, if Word's behaviour of copying out is wanted.

### M2. Size declarations in groups are drawn relative to their surroundings, but TeX's sizes are absolute
Repro: `size1.py`, article 10pt. Each row gives the page's size, then TeX's size.

| text | page | TeX |
|---|---|---|
| `\section{Head {\small x}}` | 12.96pt | 9pt |
| `{\Large A {\small x}}` | 12.96pt | 9pt |
| `{\Large A {\normalsize x}}` | 14.4pt | 10pt |
| `{\small\Large x}` | 12.96pt | 14.4pt |
| `\footnote{{\Large x}}` | 11.52pt | 14.4pt |
| `\footnote{{\normalsize x}}` | 8pt | 10pt |

Lines break in different places as a result.

Cause: src/app.css:2083–2091 use `calc(var(--z-…) * 1em)`, and there is no `.y.y-z-normalsize` rule.

Fix: use `calc(var(--z-X) * var(--fs))` as `.fns` already does, and add `.y.y-z-normalsize { font-size: var(--fs); line-height: … }`. For `{\small\Large x}`, the model should keep only the last declaration of a run.

### M3. Quick Parts add packages that change the rest of the document, or leave commands undefined
Repro: `qp1.py`. A part `\uline{under} \hl{mark}` inserted into a document that uses `\emph` adds a bare `\usepackage{ulem}`, so ulem underlines every existing `\emph` in the PDF. The Font group itself writes `[normalem]` (src/charfmt.js:21). A part holding Rikuy's own `\dsout` or `\culine`, which charfmt defines in the preamble (charfmt.js:49, :78) and which are not packages, is inserted with nothing: "Undefined control sequence" in any other document.

Cause: src/quickparts.js:30 `CMD_PKG` maps names to packages only, without options or definitions. src/cmd/parts.js:189 passes no options.

Fix: give ulem's entry `{ ulem: { normalem: true } }`, as charfmt does. Carry charfmt's `defs` (dsout, culine, Rikuy's hl) through the same preamble path the Font group uses.

### M4. Moving a picture out of the middle of a paragraph splits that paragraph in two
Repro: `pic2.py`. The source is `Joined part one\n\begin{figure}…\end{figure}\njoined part two.`, which TeX sets as one paragraph. Drag the figure below "Bottom para". The result is `Joined part one\n\njoined part two.`: two paragraphs, a new indent, and a different PDF.

Cause: src/cmd/move.js:151 sets `gap = nl` whenever there is no blank line before the figure, whether or not there was one after it.

Fix: `const blankAfter = /\n[ \t]*\r?\n/.test(src.slice(W.e, z)); const gap = !blankBefore && blankAfter ? nl : ''`, so the paragraphs on either side keep the relation they had.

### M5. A wrapfigure next to a short paragraph: the page stops wrapping at the paragraph's end, but TeX keeps wrapping
Repro: `wrapfig/main.tex` (a 6 cm tall wrapfigure, a two-line paragraph, then a long paragraph); `tc.sh wrapfig`, then `pdftotext -layout`. TeX sets the second paragraph's lines short, beside the figure. The page makes the first paragraph `display: flow-root` (src/app.css:2076), so it grows to the float's height, leaves white space under its two lines, and starts the second paragraph below the figure at full width.

Fix: let the float overhang into the next items rather than using flow-root on P. Alternatively, pair W with as many following paragraphs as its height needs, which is what wrapfig's line count does.

### M6. Dragging words from inside formatting removes the formatting and leaves a stray space
Repro: `drag1.py`, cases 2 and 5. Drag "one two" out of `\textbf{bold one two}`. The source becomes `be one two ta … \textbf{bold }`: the moved words are no longer bold, and `\textbf{bold }` keeps a space before `}`, so TeX sets two spaces before "end". Word keeps character formatting on a move. Rikuy's own Quick Part save already keeps it (`wholeGroups`).

Cause: src/cmd/move.js:86 uses `selectionLatex`, which is Copy's text and drops wrappers it is inside. The smart space at move.js:82 takes a space only when the next character is `[ .,;:!?)]`, not `}`.

Fix: re-wrap the moved text in the inline wrappers that enclose [a, b] (the model's styAtom `cmd`s, from the innermost out). Allow `}` before the following space in the smart-space test.

## Low

- L6. Firefox has no `document.caretRangeFromPoint`. `posAtPoint` (src/cmd/move.js) then returns null, and the drop handler has already called `preventDefault`, so text drops and picture moves do nothing there. Fall back to `caretPositionFromPoint`.
- L7. wrapfigure `i`/`o` are mapped as one-sided (o→r, i→l) even with `twoside`, where even pages swap (src/model.js, `side`).

Checked and found sound: fields in the incremental model (`\thesection` after a section is inserted before it, `\thetitle` after `\title` changes, `\thepage`/LastPage filled after pagination; `fld1.py`); foreign HTML drops (scripts, `onerror` and `javascript:` links inert, specials escaped; `drag2.py` d); a picture dropped on a minipage, footnote or center (no breakage); `tikzPoints` refusing relative, polar and macro coordinates and converting mm; caret, typing and arrows in a wrapped paragraph (`wrap4.py`); titling with scrartcl, report, twocolumn and `\title` before `\documentclass` (all compile). - Cause: src/layout.js:717. `apply` skips a page whose signature (uid, a, b, sb, fill) is unchanged. - Fix: count each measuring (`it.mv = (it.mv || 0) + 1` in `measure`) and include `e.it.mv` in the page signature. Alternatively, skip a page only when every entry's element is still inside it.

**N2 (High, but needs a rare construct). The Form reader takes `\verb|\end{Form}|` for the Form's end.**
- Repro `form2.py`, case verb_inside: a Form containing `Close it with \verb|\end{Form}| here.`, with the caret after the Form.
- The `\end{Form}` is cut out of the `\verb`, leaving `\verb||`, and a second `\end{Form}` is added at the end of the body. TeX: `\begin{document} ended by \end{Form}`.
- Cause: src/forms.js:53, whose pattern does not skip `\verb<c>…<c>` or `\lstinline`.
- Fix: add `\\verb\*?(.)[^\n]*?\1` and the same for `\lstinline` to the skipped tokens.

**N3 (Medium). memoir's titlingpage is paginated like article's titlepage.**
- Repro `cover2.py`, twoside memoir. TeX makes 3 pages: the cover, a blank page, then the body, numbered 1. The page draws 2 pages and numbers the body 2.
- Cause: src/model.js:2178 resets the number only when the document is one-sided, and adds no recto break.
- Fix: for titlingpage, always reset to page 1, and in twoside documents add a break to the next right-hand page.

**N4 (Low). The caret cannot cross the empty float.**

**N5 (Low). M6 leaves a leading space inside the wrapper.**
