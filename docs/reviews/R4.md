# Hostile review of d22d8ba (R4, PR 66)

Verdict: **request changes.** The comments only link does not hold. A stranger with a "Can comment only" link can put arbitrary TeX into the author's PDF in two independent ways, and the author is told only that comments arrived ("0 changes and 2 comments"). Everything else held up or has only medium and low defects.

Repro material is in `/tmp/review-r4-out/`. The browser scripts run from the worktree's `test/` folder with `dist/` built from d22d8ba (`dist/tex` hard linked from the main checkout; `tex/engine.js` is unchanged since that tree was built).

## High

### H1. A comment line with a bare CR carries TeX code past every check
`src/share.js:278` (`WHOLE`), `:279` (`isComment`), `:155` (`LINE`), `:304` (`commentsOf`); `src/diff.js` `hunks()` splits on `\n` only.

To Rikuy, a line is text up to `\n`. TeX (web2c `input_line`, and LuaTeX and XeTeX too) also ends a line at a lone `\r`. So `% comment (Eve): fine\r\textbf{X}\n` is one comment line for `onlyComments` and `commentsOf`, but two lines for TeX, and the second one runs. `unpackShare` keeps `\r` in file text.

- Unit check: `node /tmp/review-r4-out/cr_commentsOf.mjs` prints `CR: dropped 0 injected kept: true onlyComments: true`.
- Browser check: `python3 /tmp/review-r4-out/r4_attack.py`, ATTACK 1. The author shares a comments only link, the reader's copy comes back, and `main.tex` holds the CR line. The author's toast says "A coauthor's copy is in: 0 changes and 2 comments".
- Compile: the author's resulting files, in `/tmp/review-r4-out/attackdoc/`, compiled with the page's own pdfLaTeX (`dev/texrun.py`). The PDF reads "First line of text [1]. CRINJECTED". The same happens with desktop pdfTeX (`/tmp/review-r4-out/cr/`).

Fix: in `takeBack`, refuse any file of a comments only copy that holds a `\r` that is not part of `\r\n` (or turn CRLF into LF and then refuse any `\r`). Change `[^\n]` to `[^\n\r]` in `WHOLE`, `COMMENT_LINES` and `LINE`. Add a case to `share.test.mjs`.

### H2. Comment lines are taken into every file, including `.bib`, where `%` is not a comment
`src/collab.js:272-280` runs `commentsOf` on every shared file whatever its type. `commentsOf` has no file check.

BibTeX does not treat `%` as a comment: it reads an `@` anywhere outside an entry. So `% comment (Eve): see @preamble{ "\textbf{X}" }` in `refs.bib` puts `\textbf{X}` into the `.bbl`, and TeX runs it.

- Browser check: `r4_attack.py`, ATTACK 2. `refs.bib` comes back holding the line.
- Compile: `attackdoc/` gives "Second line stays. BIBINJECTED" in the PDF. Desktop BibTeX does the same (`/tmp/review-r4-out/bib/`).

The same holds for any project file that is not LaTeX source: `.sty`, `.cls` and `.cfg` have no `\begin{document}`, so the preamble rule never applies to them; data files read by pgfplots, csvsimple or datatool are also exposed.

Fix: take comment lines only in `.tex` and `.ltx` files that the model reads as body text. Keep every other file of a comments only copy exactly as the base had it. Add a case.

## Medium

### M1. The R4 guard is bypassed by relabelling the copy
`src/collab.js:163-170`. The guard refuses only `role === 'back'` copies whose base is unknown. If the same reader sends a link with role `coauthor` (or with no sender) under the project's name and main file, `openLinked` loads it over the author's project. The author's text survives only as the "Before opening a shared document" version, and the author becomes a guest of "A coauthor" in their own document.

- Browser check: `r4_attack.py`, ATTACK 3. The author's `main.tex` now reads "SECOND LINE REWRITTEN" and `guest` is true.

The behaviour existed before for any link, but it defeats the claim that a copy whose base is renamed can no longer bring every edit in.

Fix: a link from someone else whose name and main match a project this browser keeps opens as a project of its own ("Paper (from Eve)"), at least where that project was ever shared for comments only, and never over the original without the author confirming.

### M2. The comment line test is syntactic; TeX's context decides
`src/share.js:188` (`VERBATIM`) and `:304`.

- Where the body sets `\catcode`\%=12`, a comment line is typeset and the rest of the line is executed. `node /tmp/review-r4-out/catcode.mjs` plus pdflatex on `cat/main.tex` prints "% comment (Eve): ok CATINJECTED".
- `VERBATIM` misses `tcblisting`, `VerbatimOut` (which writes a file), `luacode*`, `pycode`, `sagesilent`, `asy`, `gnuplot`, `scontents` and `verbatimwrite`. A comment line added in a `tcblisting` is printed in the listing (same repro). In code environments it breaks the run.

Both need an unusual document, which is why this is Medium and not High.

Fix: accept a comment line only where the model places it in ordinary paragraph or vertical text (the model already knows its verbatim-like environments), and refuse all comment lines in a file that changes the catcode of `%`.

### M3. A Word endnote loses every block that is not a paragraph on import
`src/wordnotes.js:140`. `endnotesTex` keeps only `Para` and `Plain` blocks. A table, list or code block in a Word endnote is dropped without a word.

- Repro: `node /tmp/review-r4-out/wordnotes_table.mjs` gives `\endnote{First paragraph.\par \par LASTPARA}`. The same table in a footnote comes back as a `longtable`.

Fix: for a marked note with any other block, write its body with pandoc's LaTeX writer, as footnotes are written, and rename `\footnote` to `\endnote` afterwards. Or leave such a note as a `\footnote` and say so.

### M4. Changes are credited to the wrong author when two people's edits touch
`src/review.js:164-171`. `whoAt` looks for a deletion mark within 2 characters, and an unknown deletion falls to the neighbouring insertion's author.

- Repro: `node /tmp/review-r4-out/authors.mjs`.
  - I type "big " and Eve then deletes "brown ": the change is `Me:["brown","big"]`, so Eve's deletion is shown as mine.
  - Eve deletes "jumps" and I then delete "fox " before it: the change is `Eve:["fox jumps",""]`.
- "Reject All by Eve" then rejects my deletion too. This is recoverable by undo.

Fix: keep the deleted length with each deletion mark and match marks to the diff's `-` parts by offset and length. Or cut changes at segment boundaries before the word level grouping.

- **Phones at 390 and 360 px.** The Thesaurus pane, Mark Citation, Footnote and Endnote, Share with its new permission select, and Show Markup all fit inside the screen, with no page errors.

## Still open

**V1. Medium: some catcode forms pass `PERCENT_CATCODE`, and the injected TeX runs** (`src/share.js:311`). In a document that makes `%` ordinary with any of the forms below, a comment line is taken and its tail is executed. Desktop pdflatex typesets "% comment (Eve): EXEC" with `\textbf` applied (`bodyat.mjs`, `bodyat2.mjs`; files in `/tmp/review-r4-out/body/`). The forms:
- `\catcode`\^^25=12`
- `\ExplSyntaxOn\char_set_catcode:nn {37} {12}`
- `\char_set_catcode_other:n {37}`
- `\catcode\numexpr36+1\relax=12`

These are rare, and only an author's own document can contain them. Fix: in any TeX file, treat any occurrence of `catcode`, `cctab`, `makeother`, `@sanitize`, `dospecials` or `^^` as "no comment lines", matching on the bare words, not on syntax.

**V2. Medium, older behaviour that the fix's claim does not cover: a link naming no sender still opens over a kept project** (`src/collab.js`, `taken`: `!!by && …`). A hand built `#share=` link without `by` under the author's project name replaced "cmonly2". The author's text survives only as a version, with the toast "The document from the link is open. The one you had is under Review, Versions." `#tex=` links take the same route under the name "main.tex". So a comments only reader can still replace the author's open document by sending such a link. Repro: browser ATTACK 4 in `r4_attack2.py`. Fix: apply `taken` without a sender too, naming the project "Name (from a link)".

**V3. Low: two ways a comment line is still printed rather than ignored** (`bodyAt`, `src/share.js:369`):
- `\verb|}|` earlier in the block throws off the brace count, so a line inside a multi-line `\url{…}` is taken and printed in the URL, which is also the link target.
- A file that the document both `\input`s and lists with `\lstinputlisting` takes the line, and the listing prints it.

Both print text; neither runs code.

**V4. Low, usability: a legitimate comment under a line with `%` in an `\href` URL is refused** (`bodyat3.mjs`). The brace counter reads the URL's `%` as a comment and loses the closing `}`, so the comment is dropped and counted as "left out".
